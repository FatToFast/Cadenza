# 케이던스 허용 구간과 템포 정책 설계

작성일: 2026-07-14

## 1. 목표

Cadenza의 목표 케이던스를 곡마다 강제로 정확히 맞추지 않고, 사용자가 정한 기준 케이던스부터 최대 10 SPM 높은 범위 안에서 원곡 템포를 우선 사용한다. 원곡 템포를 유지할 수 없을 때만 제한적으로 속도를 높이며, 음질을 크게 훼손하는 곡은 재생하지 않는다.

기본 기준 케이던스는 180 SPM이다. 따라서 기본 허용 구간은 180~190 SPM이다. 예를 들어 원곡이 92 BPM이면 원곡 속도에서 184 SPM, 95 BPM이면 190 SPM으로 해석한다.

## 2. 확정된 제품 정책

- 사용자가 조절하는 값은 `기준 케이던스`다.
- 기본 기준 케이던스는 180 SPM이다.
- 곡별 허용 구간은 `기준 케이던스...기준 케이던스 + 10`이다.
- 허용 구간은 상향 단방향이다. 기준보다 낮은 케이던스를 원곡 속도 후보로 자동 채택하지 않는다.
- 전체 케이던스 상한은 200 SPM이다. 기준이 195라면 허용 구간은 195~200이다.
- 기준 케이던스 조절 범위는 140~200 SPM이다.
- 원곡 속도 후보가 허용 구간 안에 있으면 재생속도 1.0을 사용한다.
- 원곡 속도 후보가 없으면 기준 케이던스에 맞추되 재생속도 1.0~1.25만 허용한다.
- 1.25배를 초과해야 하는 곡은 큐에서 자동으로 건너뛴다.
- 단일 곡이 허용되지 않으면 재생을 시작하지 않고 이유를 안내한다.
- 원곡보다 느린 재생은 사용하지 않는다.

## 3. 단일 템포 판단 모델

현재 `BPMRange.tempoPlan`, `BPMRange.foldedMusicalTarget`, `RunningCadenceFit`, UI 표시 로직이 각각 템포를 해석해 서로 다른 결론을 낼 수 있다. 이를 하나의 `TempoPlan` 결과로 통합한다.

`TempoPlan`은 최소한 다음 값을 제공한다.

- `baseCadence`: 사용자가 정한 기준 케이던스
- `allowedCadenceRange`: 기준부터 최대 +10까지의 허용 구간
- `effectiveCadence`: 현재 곡에 실제 적용되는 케이던스
- `musicalTargetBPM`: 재생속도 계산에 사용하는 음악 템포
- `playbackRate`: 실제 재생속도
- `mode`: 원곡 속도 유지 또는 제한적 속도 조절
- `playability`: 재생 가능 또는 건너뛰기
- `rejectionReason`: 배속 상한 초과 등 재생 불가 사유

`RunningCadenceFit`과 화면, 메트로놈, Live Activity, 큐 자동 전진은 이 결과를 소비한다. 별도의 배수 후보로 다시 계산하지 않는다.

## 4. 템포 결정 순서

### 4.1 입력 검증

원곡 BPM이 유효하지 않으면 템포 계획은 재생 불가 상태를 반환한다. 기존의 120 BPM 가정값은 화면 안내를 위한 임시값으로만 사용하고, 확인되지 않은 값을 근거로 곡을 크게 변속하지 않는다.

### 4.2 원곡 속도 후보 우선

원곡 BPM에 1, 2, 4를 곱해 걸음 케이던스 후보를 만든다. 후보 중 허용 구간 안에 있는 값이 있으면 재생속도 1.0을 선택한다.

예시:

- 기준 180, 원곡 90 BPM → 180 SPM, 1.0배
- 기준 180, 원곡 92 BPM → 184 SPM, 1.0배
- 기준 180, 원곡 95 BPM → 190 SPM, 1.0배
- 기준 180, 원곡 89 BPM → 178 SPM은 하한 미만이므로 원곡 속도 후보로 채택하지 않음

### 4.3 제한적 속도 조절

원곡 속도 후보가 없으면 2의 거듭제곱 계열로 기준 케이던스에 대응하는 음악 목표 BPM을 계산한다. 재생속도가 1.0 이상 1.25 이하이면 기준 케이던스를 `effectiveCadence`로 사용한다.

예시:

- 기준 180, 원곡 89 BPM → 음악 목표 90 BPM, 약 1.011배, 180 SPM

### 4.4 재생 거부

계산된 재생속도가 1.25를 초과하거나 원곡보다 느리게 재생해야 하면 재생 불가 상태를 반환한다.

- 큐: 해당 곡을 건너뛰고 다음 재생 가능한 곡을 찾는다.
- 단일 곡: 재생을 시작하지 않고 `케이던스 범위에 맞지 않는 곡` 안내와 원인을 표시한다.
- 큐 전체가 재생 불가하면 자동 전진을 중단하고 사용자에게 안내한다.

## 5. 원곡 BPM과 옥타브 처리

원곡 BPM은 메타데이터 또는 분석 결과를 그대로 보존한다. 목표 케이던스에 가깝다는 이유로 87 BPM을 174 BPM으로 자동 덮어쓰지 않는다.

- 자동 옥타브 스냅은 제거한다.
- 87/174처럼 분석 자체가 모호한 경우의 수동 선택 UI는 유지한다.
- 사용자가 수동으로 고른 원곡 BPM만 override 저장소에 영속한다.
- 템포 폴딩은 원곡 BPM 값을 변경하지 않고 `TempoPlan` 내부에서 처리한다.

## 6. 사용자 인터페이스

### 6.1 메인 케이던스 표시

- 큰 숫자: `effectiveCadence`
- 보조 정보: `기준 180 · 허용 180~190`
- 원곡 속도 유지 시: `원곡 속도`
- 속도 조절 시: `재생속도 1.06배`
- 원곡 BPM은 `원곡 92 BPM`처럼 별도로 표시한다.
- 기존 `원곡 → 목표` 화살표는 제거한다. 음악 BPM과 걸음 SPM을 같은 축으로 오해하게 만들기 때문이다.
- 재생속도는 한 위치에서만 표시한다.

### 6.2 조절 컨트롤

- 슬라이더 범위: 140~200 SPM
- 단계: 1 SPM
- 빠른 조절: -5/+5
- 기본값 복원 버튼: `↺ 180` 또는 `기본 180`으로 리셋 동작을 명시한다.
- 버튼과 슬라이더에 VoiceOver 라벨과 값을 제공한다.
- 빠른 조절 버튼의 최소 터치 높이는 44pt다.

### 6.3 재생 컨트롤

`playbackControls`는 화면에 한 번만 렌더링한다. 트랙 정보 분기 내부의 중복 호출을 제거하고 하단의 공통 컨트롤을 유지한다.

### 6.4 잠금화면과 Live Activity

- 대표 SPM과 호흡 애니메이션은 `effectiveCadence`를 사용한다.
- 기준 케이던스는 작은 보조 정보로 표시한다.
- 원곡 BPM은 SPM으로 표시하지 않는다.

## 7. 설정 영속성

다음 값은 앱 재시작 후에도 유지한다.

- 기준 케이던스
- 메트로놈 켜짐/꺼짐
- 메트로놈 볼륨

저장값은 허용 범위로 클램프하고 잘못된 값은 기본값으로 복구한다.

## 8. BPM 분석 회복성

이 작업의 핵심 템포 정책과 분리하되 다음 후속 작업으로 처리한다.

- 외부 API BPM은 프리뷰 분석 또는 사용자 보정으로 반박할 수 있어야 한다.
- 프리뷰 분석 실패는 영구 실패가 아니라 제한된 재시도 횟수 또는 TTL을 가진다.
- 수동 BPM override는 항상 자동 결과보다 우선한다.
- 외부 API와 프리뷰가 크게 다르면 자동 확정하지 않고 확인 상태로 전환한다.

## 9. 검증에서 함께 해결할 기존 불일치

- `RunningCadenceFit`의 `[1, 1.5, 2, 3]` 후보와 실제 2의 거듭제곱 폴딩 불일치
- 정확한 원곡 BPM을 목표 케이던스 쪽 옥타브로 자동 덮어쓰는 동작
- `원곡 → 목표` 문구와 실제 재생속도의 수학적 모순
- Live Activity에서 원곡 BPM을 SPM으로 표시하는 동작
- 90~99 SPM 표시와 실제 메트로놈 2배 클릭의 불일치
- 재생 컨트롤 중복 렌더링
- 재생속도 중복 표시와 원곡/원본 용어 혼용
- BPM 디스플레이와 슬라이더의 VoiceOver 정보 부족

## 10. 테스트 전략

### 10.1 순수 템포 정책 테스트

- 기본 180에서 원곡 90/92/95 BPM이 각각 180/184/190 SPM, 1.0배가 되는지 검증
- 원곡 89 BPM이 178 SPM으로 하향 드리프트하지 않고 약 1.011배로 180 SPM이 되는지 검증
- 원곡 속도 후보가 191 이상이면 기본 180~190 구간에서 거부되는지 검증
- 속도 조절이 1.25 이하이면 허용되고 초과하면 거부되는지 검증
- 기준 케이던스를 175로 변경하면 허용 구간이 175~185로 이동하는지 검증
- 기준 195에서 허용 상한이 200으로 클램프되는지 검증
- 잘못된 BPM과 케이던스 입력을 안전하게 거부하거나 클램프하는지 검증

### 10.2 통합 테스트

- `AudioManager`의 재생속도, 메트로놈 BPM, 실제 케이던스가 같은 `TempoPlan`과 일치하는지 검증
- `RunningCadenceFit`이 실제 재생속도 및 재생 가능 여부와 일치하는지 검증
- 원곡 BPM이 자동 옥타브 스냅으로 변경되지 않는지 검증
- 메트로놈 설정이 재생성 후 복원되는지 검증
- 큐가 재생 불가 트랙을 건너뛰고 무한 순환하지 않는지 검증

### 10.3 UI와 Live Activity 검증

- 상태별로 재생 컨트롤이 한 번만 나타나는지 검증
- 큰 숫자, 허용 범위, 재생속도 문구가 동일한 계획을 설명하는지 확인
- VoiceOver가 기준/허용/실제 케이던스를 하나의 의미 있는 정보로 읽는지 확인
- Live Activity 대표 SPM과 펄스가 실제 케이던스를 사용하는지 확인

## 11. 구현 단계

1. 단일 `TempoPlan`과 단방향 허용 구간, 배속 상한, 재생 가능 여부를 구현한다.
2. `AudioManager`와 `RunningCadenceFit`을 단일 계획에 연결한다.
3. 자동 옥타브 스냅을 제거하고 원곡 BPM을 보존한다.
4. 큐 건너뛰기와 단일 곡 재생 거부 흐름을 연결한다.
5. BPM 디스플레이, 조절 컨트롤, Live Activity를 새 의미에 맞춘다.
6. 재생 컨트롤 중복과 접근성 문제를 정리한다.
7. 메트로놈 설정을 영속한다.
8. BPM 분석 재시도와 교차검증은 후속 단계로 구현한다.

## 12. 범위 제외

- 실제 케이던스 센서 측정
- Apple Watch 또는 HealthKit 연동
- 달리는 중 자동으로 기준 케이던스를 변경하는 기능
- 원곡보다 느린 재생 허용
- 사용자가 허용 폭 10 SPM 자체를 조절하는 고급 설정
