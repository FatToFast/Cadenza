# Apple Music 현재 플레이리스트 선택 설계

## 1. 목표

Apple Music 플레이리스트 재생 중 다음 두 문제를 함께 해결한다.

- 플레이리스트 후반부의 곡을 직접 선택했을 때 선택한 곡이 아니라 다른 곡이 즉시 재생되는 문제
- 재생 중 다른 곡을 고르려면 Apple Music 플레이리스트 전체를 다시 조회해야 하는 불편

성공 조건은 사용자가 누른 플레이리스트 항목이 정확히 재생되고, 같은 플레이리스트 안에서는 네트워크 재조회 없이 곧바로 다른 곡을 선택할 수 있는 것이다.

## 2. 확인된 원인

`AppleMusicStreamingPlaylistView`는 `playlist.with(.entries)`로 상세 플레이리스트의 엔트리를 가져오지만 상세 플레이리스트 객체는 버리고 엔트리 배열만 보관한다. 곡을 선택하면 상세 조회 전의 원래 `Playlist`와 상세 조회에서 얻은 `Playlist.Entry`를 함께 컨트롤러에 전달한다.

컨트롤러는 이 서로 다른 조회 컨텍스트의 두 값을 `ApplicationMusicPlayer.Queue(playlist:startingAt:)`에 넘긴다. 여러 후반부 항목을 선택해도 같은 항목으로 즉시 수렴하는 실기기 증상은 템포 자동 스킵이 아니라 큐 생성 시 시작 엔트리 해석이 어긋나는 경계와 일치한다.

## 3. 선택한 접근

이미 불러온 `[Playlist.Entry]`를 단일 진실 원천으로 사용한다.

- 초기 재생 큐는 `ApplicationMusicPlayer.Queue(for: entries, startingAt: selectedEntry)` 형태의 명시적 엔트리 큐로 구성한다.
- 선택한 엔트리는 반드시 큐를 구성한 배열 안에서 안정적인 식별자로 다시 찾는다.
- 플레이리스트 이름, ID, 엔트리 배열, 현재 엔트리 식별자를 스트리밍 컨트롤러가 현재 세션으로 보관한다.
- 같은 플레이리스트에서 곡을 다시 고를 때는 보관한 배열로 큐를 재구성하므로 Apple Music 플레이리스트 목록이나 엔트리를 다시 조회하지 않는다.
- MusicKit이 준비한 실제 현재 엔트리가 요청한 엔트리와 다르면 재생을 시작하지 않고 오류를 표시한다.

컨테이너 큐의 지연 로딩 이점보다 선택 정확성과 현재 플레이리스트 재사용을 우선한다. 현재 구현은 BPM 표시와 프리로드를 위해 어차피 엔트리 배열 전체를 먼저 불러오므로 추가 조회 비용도 발생하지 않는다.

## 4. 상태 모델

스트리밍 컨트롤러는 선택적으로 다음 현재 플레이리스트 세션을 보관한다.

- 플레이리스트 ID와 표시 이름
- 원본 순서를 유지한 `[Playlist.Entry]`
- 현재 엔트리의 안정적인 선택 식별자
- 사용자가 직접 선택한 전환인지, 자연 재생/자동 전진인지 구분하는 전환 의도

선택 식별자는 플레이리스트 엔트리 ID를 우선한다. 큐가 Song ID만 노출하는 경우에는 엔트리의 내부 Song ID를 보조 키로 사용하되, 중복곡이 있는 플레이리스트에서는 배열 위치를 함께 사용해 모호성을 없앤다.

## 5. 재생 데이터 흐름

### 5.1 최초 플레이리스트 선택

1. 플레이리스트 상세 조회로 엔트리 배열을 가져온다.
2. 사용자가 누른 엔트리 ID를 배열에서 다시 찾는다.
3. 컨트롤러에 플레이리스트 메타데이터, 전체 엔트리 배열, 선택 인덱스를 전달한다.
4. 동일 배열과 선택 엔트리로 명시적 MusicKit 큐를 만든다.
5. `prepareToPlay()` 후 실제 현재 엔트리를 요청 엔트리와 대조한다.
6. 일치할 때만 재생 상태와 BPM 정책을 확정하고 재생한다.

### 5.2 재생 중 현재 플레이리스트 선택

1. 플레이어 화면의 `현재 플레이리스트` 버튼을 누른다.
2. 컨트롤러가 보관한 엔트리 배열을 즉시 시트에 표시한다.
3. 현재 재생 곡을 체크 표시와 강조색으로 구분한다.
4. 다른 곡을 누르면 캐시된 배열과 선택 인덱스로 큐를 다시 구성한다.
5. 검증이 끝난 뒤 시트를 닫고 선택한 곡을 재생한다.

`다른 플레이리스트 선택`은 시트 하단의 별도 동작으로 제공하며, 이 경우에만 기존 Apple Music 플레이리스트 조회 화면을 연다.

## 6. 템포 정책

사용자 직접 선택과 자동 진행을 구분한다.

- 직접 선택: 템포 범위 밖이어도 다른 곡으로 자동 이동하지 않는다. 선택한 곡을 유지하고 재생을 멈춘 뒤 `케이던스 범위에 맞지 않는 곡입니다`를 표시한다.
- 자연스러운 곡 종료, 자동 전진: 재생 불가 곡을 건너뛰고 다음 재생 가능한 곡을 찾는 기존 정책을 유지한다.
- 다음/이전 버튼: 사용자가 특정 곡을 직접 고른 것은 아니므로 기존 큐 탐색 정책을 적용하되, 실제 이동 결과를 화면에 즉시 반영한다.

## 7. 인터페이스

Apple Music 플레이리스트 재생 상태의 곡 정보 영역에 `현재 플레이리스트` 버튼을 추가한다.

시트 구성은 다음으로 제한한다.

- 내비게이션 제목: 현재 플레이리스트 이름
- 곡 행: 제목, 아티스트, BPM 상태
- 현재 곡: 체크 표시와 강조
- 로딩 상태: 없음. 이미 보관된 엔트리를 표시한다.
- 하단 보조 동작: `다른 플레이리스트 선택`

단일 Apple Music 검색 결과 재생이나 로컬 파일 재생에는 이 버튼을 노출하지 않는다. 로컬 재생은 기존 `LocalQueueSheet`를 유지한다.

## 8. 오류 처리와 방어

- 선택 ID가 캐시된 배열에 없으면 기존 재생을 유지하고 `선택한 곡을 현재 플레이리스트에서 찾을 수 없습니다`를 표시한다.
- MusicKit 큐 준비 후 실제 시작 항목이 요청 항목과 다르면 재생하지 않고 `선택한 곡을 재생 대기열에 설정하지 못했습니다`를 표시한다.
- 재생 권한 만료나 지역 제한은 기존 스트리밍 오류 흐름을 사용한다.
- 현재 플레이리스트 세션은 단일곡 재생이나 로컬 재생으로 전환할 때 제거한다.
- 큐 재구성 중 오래된 비동기 완료가 새 선택을 덮어쓰지 않도록 기존 selection generation과 mutation gate를 유지한다.

## 9. 테스트

MusicKit 런타임에 직접 의존하지 않는 선택 계획 모델을 만들고 다음을 단위 테스트한다.

- 뒤에서 3, 4, 5번째 항목을 선택하면 각각 정확한 인덱스를 반환한다.
- 여러 선택이 뒤에서 2번째 항목으로 수렴하지 않는다.
- 중복 Song ID가 있어도 Playlist.Entry ID 또는 인덱스로 올바른 항목을 선택한다.
- 캐시에 없는 ID는 큐 재생을 요청하지 않는다.
- 직접 선택한 재생 불가 곡은 자동 스킵하지 않는다.
- 자연 진행에서 재생 불가 곡은 기존처럼 자동 스킵한다.
- 큐 준비 후 실제 항목 불일치는 재생 실패로 처리한다.
- 새 선택이 이전 비동기 재생 완료보다 우선한다.

실기기에서는 문제가 발생했던 플레이리스트의 뒤에서 3, 4, 5번째 곡을 각각 선택해 제목과 실제 오디오가 모두 선택과 일치하는지 확인한다. 이어서 현재 플레이리스트 시트에서 네트워크 재조회 없이 다른 곡으로 전환되는지 확인한다.
