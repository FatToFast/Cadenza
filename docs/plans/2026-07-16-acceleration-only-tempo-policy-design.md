# 감속 없는 전곡 재생 템포 정책 설계

작성일: 2026-07-16

## 1. 결정

Cadenza는 유효한 원곡 BPM이 있는 곡을 케이던스 범위 때문에 차단하지 않는다. 재생속도는 항상 1.0배 이상이며, 원곡 속도로 허용 케이던스 구간에 들어오지 않는 곡은 가장 가까운 상위 폴딩 목표까지 가속한다.

이 문서는 `2026-07-14-cadence-window-tempo-policy-design.md`의 배속 상한, 재생 거부, 자동 건너뛰기 정책을 대체한다. 감속 금지와 기준 케이던스부터 +10 SPM까지의 원곡 속도 허용 구간은 유지한다.

## 2. 제품 원칙

- 기본 기준 케이던스는 180 SPM이다.
- 원곡 속도 허용 구간은 `기준 케이던스...기준 케이던스 + 10`이며 전체 상한 200 SPM을 넘지 않는다.
- 허용 구간 안에 원곡 속도 케이던스가 있으면 1.0배로 재생한다.
- 허용 구간 밖의 곡은 감속하지 않고 상위 폴딩 목표까지 가속한다.
- 유효한 BPM이 있는 곡에는 최대 배속에 따른 재생 거부 조건을 적용하지 않는다.
- 큰 폭의 가속은 정보 또는 경고로 표시할 수 있지만 곡 선택과 재생을 막지 않는다.
- BPM이 없거나 유효하지 않은 경우에만 분석, 재분석 또는 수동 입력을 요청한다. 이 상태를 `케이던스 범위에 맞지 않음`으로 표현하지 않는다.

## 3. 검토한 대안

### 3.1 채택: 허용 구간 우선, 나머지는 상위 폴딩 가속

원곡 속도를 보존할 수 있는 180~190 SPM 곡은 그대로 듣고, 나머지는 가장 가까운 상위 폴딩 목표로 가속한다. 감속과 재생 차단이 모두 없어서 제품 목적에 가장 잘 맞는다.

### 3.2 기각: 모든 곡을 정확히 기준 케이던스로 강제

92 BPM처럼 원곡 속도에서 이미 184 SPM인 곡까지 180 SPM으로 감속하게 된다. 원곡 보존과 감속 금지 요구를 위반한다.

### 3.3 기각: 큰 가속이 필요한 곡 차단

음질 변화는 줄지만, 음악 속도를 케이던스에 맞추는 앱에서 곡을 선택할 수 없게 된다. 사용자 의도와 제품 가치에 어긋난다.

## 4. 템포 결정 알고리즘

1. 기준 케이던스를 140~200 SPM으로 정규화하고 상향 10 SPM 허용 구간을 만든다.
2. 원곡 BPM에 1, 2, 4를 곱한 원곡 속도 케이던스 후보를 계산한다.
3. 후보 하나가 허용 구간에 있으면 원곡 속도 1.0배와 해당 케이던스를 사용한다.
4. 후보가 없으면 `기준 케이던스 × 2^k` 계열에서 원곡 BPM 이상인 가장 작은 음악 목표 BPM을 선택한다.
5. `재생속도 = 음악 목표 BPM / 원곡 BPM`으로 계산한다. 이 값은 항상 1.0 이상이다.
6. 유효한 BPM이면 배속 크기와 관계없이 재생 가능한 계획을 반환한다.

원곡 BPM 입력 범위 30~300과 기준 케이던스 범위 140~200에서는 2의 거듭제곱 폴딩으로 플레이어 지원 범위 안의 상위 목표를 선택할 수 있다. 플레이어 적용부의 기존 안전 클램프는 방어 수단으로 유지한다.

## 5. 대표 사례

기준 180, 허용 180~190일 때:

| 원곡 BPM | 처리 | 재생속도 | 실제 케이던스 |
|---:|---|---:|---:|
| 87 | 90 BPM으로 가속 | 약 1.034배 | 180 SPM |
| 92 | 원곡 속도 유지 | 1.0배 | 184 SPM |
| 95 | 원곡 속도 유지 | 1.0배 | 190 SPM |
| 96 | 180 BPM으로 가속 | 1.875배 | 180 SPM |
| 120 | 180 BPM으로 가속 | 1.5배 | 180 SPM |

## 6. 인터페이스와 큐 동작

- 재생 가능한 유효 BPM 곡에는 `케이던스 범위에 맞지 않는 곡입니다` 오류를 표시하지 않는다.
- 직접 선택한 곡과 자동으로 이어진 곡 모두 동일한 가속 정책을 사용한다.
- 배속이 크다는 이유로 다음 곡으로 자동 이동하지 않는다.
- 1.25배를 넘는 경우에도 재생하며 `재생속도 1.50배`처럼 실제 적용값을 표시한다.
- 큰 폭 가속을 강조한다면 주황색 정보 배지를 사용하되 재생 버튼과 곡 선택은 활성 상태로 둔다.
- BPM 미확인 상태는 `BPM 확인 필요`로 안내하고 재분석 또는 수동 입력 복구 동작을 제공한다.

## 7. 데이터 흐름

`BPMRange.tempoPlan`이 원곡 속도 유지 여부, 상위 폴딩 목표, 재생속도, 실제 케이던스를 단일 결과로 만든다. `AudioManager`, Apple Music 스트리밍 컨트롤러, 메트로놈, `RunningCadenceFit`, BPM 표시와 Live Activity는 이 결과를 그대로 소비한다.

큐 정책은 템포 계획의 배속 크기를 재생 가능 여부로 다시 해석하지 않는다. 템포 기반 자동 건너뛰기와 직접 선택 거부는 제거하거나 도달 불가능한 호환 코드로 정리한다.

## 8. 오류 처리

- 유효하지 않은 BPM: 변속하지 않고 확인 필요 상태로 전환한다.
- Apple Music 대기열 또는 재생 API 실패: 기존 재생 오류로 안내한다.
- 플레이어가 계산된 배속 적용을 거부: 실제 API 오류를 표시하고 1.0배로 조용히 대체하지 않는다.
- 케이던스 범위 자체는 재생 오류 사유가 아니다.

## 9. 테스트 전략

- 87, 92, 95 BPM이 각각 약 1.034배/1.0배/1.0배와 180/184/190 SPM을 만드는지 검증한다.
- 96 BPM이 감속되지 않고 1.875배, 180 SPM으로 재생 가능한지 검증한다.
- 120 BPM이 차단되지 않고 1.5배, 180 SPM으로 재생 가능한지 검증한다.
- 모든 유효 BPM 계획의 재생속도가 1.0 이상이고 재생 가능인지 경계값 30~300 BPM에서 검증한다.
- 직접 선택 및 자동 큐 전환에서 템포 부적합 오류와 자동 건너뛰기가 발생하지 않는지 검증한다.
- BPM 미확인과 실제 MusicKit 오류는 기존 복구 UI가 유지되는지 검증한다.
- 전체 단위 테스트, 정적 분석, 시뮬레이터 빌드, 실기기 빌드와 대표 곡 수동 재생을 확인한다.
